# Определение ориентации текста (0° или 180°)

Решение задачи классификации ориентации кропа с текстом. Модель предсказывает
вероятность `p_180` того, что текст на изображении перевёрнут.

Метрика на платформе: **1 − Brier Score = 0.7710** (ошибка Брайера 0.2289).

## Структура проекта

Все пути — относительно корня репозитория (там, где лежит `solution.py`).

```
.
├── solution.py          ← код решения
├── model.pt             ← обученные веса (приложены)
├── submission.csv       ← готовый ответ для 20 000 картинок
├── requirements.txt     ← зависимости с точными версиями
├── setup.bat            ← создаёт venv + ставит пакеты
├── run.bat              ← запускает solution.py в venv
├── README.md            ← этот файл
└── data/                ← СЮДА кладутся тестовые картинки (см. ниже)
    └── test/
        ├── test_00000.jpg
        ├── test_00001.jpg
        └── ...
```

## Куда класть тестовые картинки

Скрипт **сам ищет** тестовые данные в нескольких стандартных местах.
Достаточно, чтобы папка с картинками существовала по одному из путей ниже —
распаковывать датасет нужно ровно так, как он выдаётся организатором.

### Поддерживаемые варианты

**Вариант A — без CSV (обычный случай для этой задачи):**

```
data/test/*.jpg
```

`image_id` берётся из имени файла без расширения (например, `test_00000`).
Именно так выглядит датасет организатора.

**Вариант B — папка test/ в корне:**

```
test/*.jpg
```

**Вариант C — папка images/ в корне или в data/:**

```
images/*.jpg
data/images/*.jpg
```

**Вариант D — с CSV-файлом:**

```
data/test.csv  +  data/test/*.jpg
test.csv       +  test/*.jpg
```

Скрипт сам распознаёт колонки `image_id` и `image_path` (или их синонимы).
Если в CSV только `image_id` — путь достраивается по имени файла в папке.

### Что делать, если данные не найдены

Скрипт напечатает **все пути, которые проверял**, и завершится с ошибкой.
Тогда нужно положить картинки в одну из перечисленных папок — перезапускать
`setup.bat` не нужно, только `run.bat`.

## Запуск (Windows)

**Шаг 1 — установка (один раз, ~2–3 минуты):**

```
setup.bat
```

**Шаг 2 — получить submission.csv (~3–4 минуты):**

```
run.bat
```

Готовый `submission.csv` появится в корне проекта (рядом с `solution.py`).

`model.pt` приложен — при его наличии скрипт **пропускает обучение** и сразу
делает инференс с TTA. Если удалить `model.pt` — `solution.py` переобучится
с нуля за ~60 минут на CPU и получит тот же результат (SEED=42 фиксирован).

**Запуск вручную (Linux/macOS/Windows):**

```bash
python -m venv venv
source venv/bin/activate          # Linux/macOS
# venv\Scripts\activate            # Windows
pip install -r requirements.txt
python solution.py
```

## Подход

### 1. Синтетическое обучение

Реальные метки для обучения не предоставлены. Вместо этого кропы с текстом
генерируются **на лету**: рендерим случайные слова системными шрифтами на
случайном фоне, а половину из них переворачиваем на 180°. Это даёт
бесплатный бесконечный поток размеченных данных и учит модель на
инвариантах текста, а не на конкретном наборе изображений.

Генератор воспроизводит формат реальных данных — вывесок, логотипов,
ценников и упаковок:

- **Формат кропа**: соотношение сторон 2:1 — 16:1 (широкие полоски),
  высота 32–128 px.
- **Текст**: 150+ слов — латиница + кириллица, названия брендов
  (PYATEROCHKA, МАГНИТ, ОТКРЫТИЕ, SANYO), 1–3 слова в кадре.
- **Размер текста**: подбирается так, чтобы занимать 60–110% ширины
  и 60–105% высоты кропа (иногда выходит за края — как в реальных фото).
- **Шрифт**: случайный из ~146 ttf/otf системной папки Windows — тонкие,
  толстые, рукописные, geometric sans, serif; полный спектр.
- **Фон**: однотонная заливка, линейный/диагональный градиент, случайный
  шум, полоски.
- **Цвет текста**: контрастный к фону (тёмный на светлом и наоборот).
- **Аугментации**: JPEG-сжатие (q=25–85), Gaussian blur, motion blur,
  perspective warp, яркость, контраст, насыщенность, зерно.

### 2. Архитектура

MobileNetV3-Small (предобучен на ImageNet) с модифицированной головой:

```
MobileNetV3-Small features  (последние 3 блока разморожены)
AdaptiveAvgPool2d((4, 1))    ← ключевая деталь
Linear(2304 → 512)
Hardswish
Dropout(0.2)
Linear(512 → 1)
```

**Почему `AdaptiveAvgPool2d((4, 1))`, а не обычный global average:**
при пулинге в одно значение модель теряет информацию «верх vs низ» букв,
а это ключевой сигнал для задачи 0°/180°. Сохранение 4 вертикальных полос
даёт модели доступ к вертикальной структуре текста. На практике это дало
существенный прирост к метрике.

**Почему backbone, а не CNN с нуля:** MobileNetV3-Small уже содержит
полезные низкоуровневые фильтры (грани, текстуры), что снижает domain gap
между синтетикой и реальными кропами. Обучение с нуля показало худший
результат.

**Почему разморожены только последние 3 блока features:**
низкоуровневые фильтры (первые блоки) универсальны и их разрушать
не нужно. Высокоуровневые — адаптируем под текст. Две группы learning rate
(3e-4 для features, 1e-3 для головы), чтобы не «снести» pretrained-веса
за несколько шагов.

### 3. Препроцессинг

- Ресайз по высоте до 64 px с сохранением пропорций (ширина до 1024 px).
- Нормализация по статистикам ImageNet.
- Паддинг до максимальной ширины в батче — только на этапе collate.

### 4. Обучение

- Loss: `BCEWithLogitsLoss` — логарифмическое правдоподобие Бернулли;
  его минимизация напрямую ведёт к минимизации метрики Brier.
- Оптимизатор: AdamW с двумя группами learning rate.
- Scheduler: CosineAnnealingLR.
- `SYN_N=20000`, `EPOCHS=12`, `batch=64`, CPU.
- Время обучения: ~55 минут на CPU (12 эпох × ~275 с).
- Финальные метрики: train loss 0.170, train acc 0.917.

### 5. Инференс с TTA

Test-Time Augmentation: каждая картинка прогоняется дважды — в исходном
виде и с поворотом на 180°. Вероятности усредняются с учётом инверсии:

```
p = (p_orig + (1 - p_flipped)) / 2
```

Это даёт бесплатный прирост качества без изменения модели. На практике TTA
сгладил распределение (std упал с 0.38 до 0.28), что положительно сказалось
на Brier.

## Воспроизводимость

- `SEED = 42` фиксирует `random`, `numpy`, `torch`.
- Точные версии пакетов — в `requirements.txt` (получены через `pip freeze`).
- `model.pt` приложен: скрипт переиспользует веса и пропускает обучение.
  Если удалить `model.pt` — `solution.py` переобучится с нуля и получит
  тот же результат (детерминированно, при том же seed и версии torch).

## Что не используется

- Внешние API — нет.
- LLM/VLM (>1B) — нет.
- Ручная разметка тестовых данных — нет.

## Что можно улучшить дальше

- **Ансамбль**: обучить 2–3 модели с разными seed и усреднить `p_180`.
  Ожидаемый прирост: +1–2%.
- **Калибровка выхода**: `p_new = 0.5 + α * (p - 0.5)` с подбором α под
  prior flipped. Требует знания примерного распределения классов на тесте.
- **Больше эпох** на большем числе сэмплов: train loss ещё падал,
  к 12-й эпохе не упёрся.
- **Pretrained-модель посерьёзнее**: EfficientNet-B0 или ConvNeXt-Tiny.
  Дадут больше, но и обучаются дольше.
- **Реальные данные**: даже 500 вручную размеченных кропов дали бы
  больший эффект, чем удвоение синтетики — это самая большая проблема
  подхода (synthetic-to-real domain gap).
