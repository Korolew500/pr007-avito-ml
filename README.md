# Определение ориентации текста (0° или 180°)

Решение задачи классификации ориентации кропа с текстом. Модель предсказывает
вероятность `p_180` того, что текст на изображении перевёрнут.

## Структура проекта

Все пути ниже — относительно корня репозитория (там, где лежит `solution.py`).

```
.
├── solution.py          ← код решения
├── model.pt             ← обученные веса (приложены)
├── submission.csv       ← готовый ответ для 20 000 картинок
├── requirements.txt     ← зависимости с точными версиями
├── setup.bat            ← создаёт venv + ставит пакеты
├── run.bat              ← запускает solution.py в venv
├── README.md            ← этот файл
└── data/                ← СЮДА кладутся тестовые картинки (см. ниже)
    └── test/
        ├── test_00000.jpg
        ├── test_00001.jpg
        └── ...
```

## Куда класть тестовые картинки

Скрипт **сам ищет** тестовые данные в нескольких стандартных местах.
Достаточно, чтобы папка с картинками существовала по одному из путей ниже —
распаковывать датасет нужно ровно так, как он выдаётся организатором.

### Поддерживаемые варианты

**Вариант A — без CSV (обычный случай для этой задачи):**

```
data/test/*.jpg
```

`image_id` берётся из имени файла без расширения (например, `test_00000`).
Именно так выглядит датасет организатора.

**Вариант B — папка test/ в корне:**

```
test/*.jpg
```

**Вариант C — папка images/ в корне или в data/:**

```
images/*.jpg
data/images/*.jpg
```

**Вариант D — с CSV-файлом (если организатор даёт разметку файлом):**

```
data/test.csv  +  data/test/*.jpg
test.csv       +  test/*.jpg
```

Скрипт сам распознаёт колонки `image_id` и `image_path` (или их синонимы —
`id`, `filename`, `path`, `filepath` и т. д.). Если в CSV только `image_id` —
путь достраивается по имени файла в соответствующей папке.

### Что делать, если ничего не найдено

Если скрипт не нашёл данные, он напечатает в консоль **все пути, которые
проверял**, и завершится с ошибкой. Тогда просто положи картинки в одну из
перечисленных выше папок — перезапускать `setup.bat` не нужно, только `run.bat`.

## Запуск (Windows)

**Шаг 1 — установка (один раз, ~2–3 минуты):**

```
setup.bat
```

**Шаг 2 — получить submission.csv (~1–2 минуты):**

```
run.bat
```

Готовый `submission.csv` появится в корне проекта (рядом с `solution.py`).

`model.pt` приложен — при его наличии скрипт **пропускает обучение** и сразу
делает инференс. Если удалить `model.pt` — `solution.py` переобучится с нуля
за ~17 минут на CPU и получит тот же результат (SEED=42 фиксирован).

**Запуск вручную (Linux/macOS/Windows):**

```bash
python -m venv venv
source venv/bin/activate          # Linux/macOS
# venv\Scripts\activate            # Windows
pip install -r requirements.txt
python solution.py
```

## Подход

### 1. Синтетическое обучение

Реальные метки для обучения не предоставлены. Вместо этого кропы с текстом
генерируются **на лету**: рендерим случайные слова системными шрифтами на
случайном фоне, а половину из них переворачиваем на 180°. Это даёт
бесплатный бесконечный поток размеченных данных и учит модель на
инвариантах текста, а не на конкретном наборе изображений.

Что варьируется в генераторе:

- **Текст**: 90+ слов — латиница (бренды, продукты) + кириллица.
- **Шрифт**: случайный из ~146 ttf/otf в системной папке Windows,
  размер подбирается под ширину кропа.
- **Фон**: однотонная заливка, линейный градиент, случайный шум.
- **Цвет текста**: контрастный к фону.
- **Аугментации**: JPEG-сжатие (q=30–85), Gaussian blur — имитируют
  реальные артефакты фото и мессенджеров.

### 2. Архитектура

Компактная CNN (~0.4M параметров), быстрая на CPU:

```
Conv(3→32)   → Conv(32→32)
Conv(32→64)  → Conv(64→64)
Conv(64→128) → Conv(128→128)
AdaptiveAvgPool2d((4, 1))
Linear(512 → 1)
```

**Почему `AdaptiveAvgPool2d((4, 1))`, а не обычный `(1)`:** при пулинге
в одно значение модель теряет информацию «верх vs низ» букв, а это
ключевой сигнал для задачи 0°/180°. Сохранение 4 вертикальных полос
даёт модели доступ к вертикальной структуре текста.

### 3. Препроцессинг

- Ресайз по высоте до 48 px с сохранением пропорций (ширина ограничена 320 px).
- Нормализация в `[-1, 1]` (mean=0.5, std=0.5).
- Паддинг до максимальной ширины в батче — только на этапе collate.

### 4. Обучение

- Loss: `BCEWithLogitsLoss` — логарифмическое правдоподобие Бернулли;
  минимизация этой функции напрямую ведёт к минимизации метрики Brier.
- Оптимизатор: AdamW (lr=3e-3, weight_decay=1e-4).
- Scheduler: CosineAnnealingLR.
- `SYN_N=12000` синтетических примеров, 8 эпох, batch=128, CPU.
- Время обучения: ~17 минут на CPU.
- Финальный train loss: 0.41 (стартовый 0.71 = ln 2).

### 5. Инференс

Батчами по 64 картинки. Для каждой отдаём `sigmoid(model(x))` как `p_180`.
Нечитаемые файлы получают нейтральное значение 0.5.

## Воспроизводимость

- `SEED = 42` фиксирует `random`, `numpy`, `torch`.
- Точные версии пакетов — в `requirements.txt` (получены через `pip freeze`).
- `model.pt` приложен: скрипт переиспользует веса и пропускает обучение.
  Если удалить `model.pt` — `solution.py` переобучится с нуля и получит
  тот же результат (детерминированно, при том же seed).

## Что не используется

- Внешние API — нет.
- LLM/VLM (>1B) — нет.
- Ручная разметка теста — нет.

## Что можно улучшить дальше

- **Pretrained backbone** (MobileNetV3-Small, EfficientNet-B0) — самый
  сильный рычаг. Даёт +3–5% к `1 − Brier`, но уже не «с нуля».
- **Больше данных** (`SYN_N=30000`, `EPOCHS=12`) — loss ещё падал, не упёрся.
- **Валидационный сплит** с другим распределением шрифтов и цветов.
- **TTA**: прогон картинки в исходном виде и повёрнутой на 180°,
  усреднение `p` и `1−p`.
